Original tier/shadow/active/protocol/streaming/concurrency/exhaustion/stale/recovery/failure/tool/cancellation/pinning/scheduler/rollback checks passed.
- Final runtime 300s mixed routing and monitor soak: **3,488 requests**, **3,322 decision evictions**, natural quota polling, no worker failure; CPA RSS KiB **69,552–81,484**, final **70,368**. Histories and responses stayed capped. Final RSS returned near the observed minimum. The fixture intentionally tests all-exhausted 503 and documents that CPA does not automatically recover a credential from 401 verification.

## Browser verification

Linux Chrome through chrome-devtools-mux used synthetic CPA 8.1.0 and isolated OMC v0.4.13. The old standalone hang came from observing the page's own theme writes. It was fixed and verified on real navigation, including system theme after manual override.

- On the standalone resource, the initial shell showed login, not diagnostics. A missing or bad key did not reveal private data; valid login showed 0.2.0 and four synthetic accounts. Forget key and 401/403 cleared the account/model/history DOM and allowed relogin. No new storage keys or URL credentials. A synthetic saved key tagged with a different API origin produced **zero** automatic monitor reads. OMC's actual same-origin iframe reused its login; fallback rejection also cleared data.
- In the browser, intercept only monitor GETs with synthetic snapshots to exercise degraded/stale/exhausted, failed worker, empty/no traffic, unknown/unoffered tier, monthly-only and reset-pending states, recovery/epoch/eviction/truncation, long and XSS-like labels as literal text, case/prefix model filtering and account search. Synthetic 404 shows unavailable with stale data labeled; 403 clears it. Actual native disable removes the page/API or reports stopped when the API survives.
- Pause and hidden-state handling yielded zero extra reads over >5s; visible resume read once. A stalled fetch plus repeated refresh clicks started exactly one read and Pause aborted it. A second stalled read aborted at 10s, backed off, then recovered on manual refresh. The Node test additionally reproduces the late-response/logout race.
- Keyboard Tab/Enter operated Pause with visible focus; 390px light layout had no body overflow (account table scrolls separately), and 1280px dark mode rendered. Screenshots are private synthetic evidence under `.local/`. Final standalone healthy view had no console errors/warnings.

To repeat: build the plugin, run `QFR_UI_FIXTURE=1 python3 tests/host_integration.py --cpa /path/to/cpa --library dist/quota-first-router.so`, then use the loopback URL `http://127.0.0.1:18319/v0/resource/plugins/quota-first-router/monitor` in Chrome. To repeat embedding, point an isolated OMC instance at that disposable CPA and navigate to the plugin menu. Use only the fixture login, not production authentication or data. Response interception proves UI rendering and controller behavior; unit/real CPA tests separately prove backend behavior. This is not six-OS browser coverage.
