# Quota First Router v0.1.0

Initial public release: tier-aware nearest-five-hour-reset scheduling for Codex OAuth accounts.

## Supported

- CLIProxyAPI **8.1.0**, Linux **amd64** with glibc **2.34+**.
- Native ABI 1 / schema 10; baseline x86-64 CPU (GOAMD64=v1).
- Codex OAuth only; Claude and mixed-provider requests delegate unchanged.

## Behavior

- Highest usable account tier first; nearest five-hour reset within that tier.
- Fresh exhausted five-hour/weekly/monthly/applicable-model quota skips an account.
- Unknown/stale quota safely delegates to CPA rather than skipping higher tiers.
- Monthly-only allowed accounts remain usable and rank after known five-hour resets in the same tier.
- Default shadow mode, one-minute polling, five-minute maximum snapshot age.
- Authenticated status explains selections and skip reasons; no model requests for quota polling.

## Installation

Install through a registry source, or verify `checksums.txt` and extract `quota-first-router.so` into CPA's plugin directory. Follow the README for the custom registry while official listing review is pending. Start in shadow mode; examine status before switching to active.

Only the Linux amd64 ZIP is supplied. Other architectures/platforms are not claimed as supported. Keep your existing account tiers; plugin priority orders scheduler plugins, not accounts.

## Checks and limits

Automated race/vet/unit checks, actual CPA synthetic streaming/concurrency/failover tests and a bounded soak precede release. The published ZIP is tested through the CPA store installer before the official listing PR. Prior private live canaries confirmed shadow/active/disable behavior; no credentials or account details are published.

Quota endpoints can change. Explicit global proxy settings must be mirrored in plugin `proxy_url`; custom credential base URLs are unsupported and reported. Pinned/retained host connections remain CPA-controlled. Native code runs inside CPA, so load only trusted builds. Disable this plugin to restore built-in routing.
