    How it works

    A quick guide to account picks, quota, and warmup.

    How the router picks an account

    For Codex-only requests, the router checks higher-priority accounts first. Among usable accounts with the same priority, it prefers the one whose five-hour quota resets sooner. CPA still handles model access, cooldowns, and requests pinned to one account.

    Example: Two accounts at priority 20 reset in 20 minutes and 2 hours. The router picks the 20-minute one. A priority 10 account doesn’t jump ahead just because it resets sooner.

    Selected or CPA decided?

    Accounts are grouped from highest to lowest routing tier. Within each tier, the monitor follows the saved order from the Oh My CPA Routing page when available; otherwise it lists accounts alphabetically.

    Selected highlights the plugin’s latest pick for the model shown, without moving its card. CPA decided means the plugin left the choice to CPA, for example when a request isn’t Codex-only or quota readings are missing.

    Example: The router picks A, but CPA retries on B. Check Request Events to see which account actually served the request. Routing activity shows picks and polling issues, not final results.

    Read the quota bars and filters

    30% left means 30% of that allowance remains. A countdown shows the expected reset; a passed timer still needs a fresh check. Not reported doesn’t mean zero.

    • All includes old and unknown readings.
    • Available shows accounts with usable readings, not a guarantee they can serve your model.
    • Exhausted shows accounts with a known quota limit hit.
    • Free shows accounts the provider confirms are Free. The plugin skips them for automatic Codex routing and warmup. CPA can still honor an explicit pin.

    Example: Open Exhausted to see which non-Free accounts hit a limit. Search narrows the cards and counts without checking quota again.

    What warmup does

    Timer not started means the five-hour window is idle. If warmup is on, the plugin can send one small request to an eligible account to start its timer, even if it was already idle. The default model is GPT-6 Luna.

    Example: Warmup sends a small request at 9:00. If it starts a window, later quota checks confirm a reset around 2:00. Warmup uses a little quota; it doesn’t add any.

    Read the quota check times

    Under Account quota, Last read is the most recent successful quota check across the accounts shown by the monitor. Next attempt is the next scheduled check for any of those accounts. Accounts can be checked at different times. Refresh reloads saved readings; it doesn’t start a quota check.

    Example: If one account was checked 56 seconds ago and another a minute ago, Last read shows 56s ago. A failed check is marked on the affected card.

    Where to change settings

    The dashboard is read-only. Use Plugin management to turn the router or warmup on or off. Warmup is off by default for new setups.

    Example: Turn off warmup but leave the plugin enabled to keep routing without sending warmup requests.
